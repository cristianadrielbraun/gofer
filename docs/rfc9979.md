# RFC 9979 interoperability

Gofer recognizes the registered IMAP and JMAP keywords as message status. It saves the server's keyword snapshot for each tracked IMAP folder copy and each JMAP Email ID. Unknown keywords remain in the snapshot and retain their existing label behavior. Gofer continues to send targeted flag and keyword changes, so updating ordinary mail flags and labels leaves unrelated keywords on the server.

Gofer reads mailbox attributes from IMAP LIST and JMAP Mailbox roles. The mailbox name alone never assigns an RFC 9979 attribute. Memos, scheduled mail and snoozed mail remain accessible through their folders and ordinary message views.

| RFC 9979 metadata | Recognized | Preserved from server | Display | Edit |
| --- | --- | --- | --- | --- |
| `$MailFlagBit0`, `$MailFlagBit1`, `$MailFlagBit2` | Yes | Yes | — | — |
| `$hasattachment`, `$hasnoattachment` | Yes | Yes | Existing attachment detection | — |
| `$memo`, `$hasmemo` | Yes | Yes | Ordinary messages and folders | — |
| `$canunsubscribe`, `$unsubscribed` | Yes | Yes | — | — |
| `$autosent`, `$imported`, `$istrusted`, `$maskedemail` | Yes | Yes | — | — |
| `$followed`, `$muted`, `$new`, `$notify` | Yes | Yes | — | — |
| `Memos`, `Scheduled`, `Snoozed` | Yes | Yes | Ordinary folders | — |

Display and edit refer to the behavior Gofer exposes today. The existing star action changes the standard flagged state. Attachment indicators still use the existing message attachment data. The new metadata adds no trust badge, notification, unsubscribe, memo, scheduling, snoozing or thread action.

## Existing installs

Database schema 154 moves previous provider status keyword labels to metadata and removes them from the ordinary label lists. A legacy keyword with uncertain copy provenance is kept on the local message as historical data. Saved searches or rules that refer to a retired status label can no longer match it as a label. The original label identities and names remain in the database so Gofer can identify these references in a future update. Genuine local labels and unrelated provider labels keep their current behavior.

The next IMAP flag sync on a folder establishes a new metadata baseline. JMAP does one resumable import to retrieve metadata previously skipped by its cursors. IMAP still represents a logical message once per folder, so duplicate UIDs with the same Message-ID in one folder share that existing representation. Gmail and Outlook API sync and local folders keep their existing behavior. IMAP accounts use the IMAP behavior above regardless of server vendor.

## Follow-up work

Flag color support needs a picker for the six nonzero colors alongside the ordinary star for zero bits, accessible color names, and targeted flag writes that clear the bits when unflagging. A later memo feature would need to pair notes with their annotated messages and present them in context. Attachment keyword handling, subscription state, advisories and thread actions each need their own provider behavior and UI. The mailbox attributes identify storage locations. Snoozing and scheduled sending need provider-specific mechanisms for timing and cancellation.

[RFC 9979](https://www.rfc-editor.org/rfc/rfc9979.html) defines the registrations and behavior. Work is tracked in [issue #159](https://github.com/cristianadrielbraun/gofer/issues/159).
