# RFC 9979 interoperability

Gofer recognizes the registered IMAP and JMAP keywords as message status. It saves the server's keyword snapshot for each tracked IMAP folder copy and each JMAP Email ID. Unknown keywords remain in the snapshot and retain their existing label behavior. Gofer continues to send targeted flag and keyword changes, so updating ordinary mail flags and labels leaves unrelated keywords on the server.

Gofer reads mailbox attributes from IMAP LIST and JMAP Mailbox roles. The mailbox name alone never assigns an RFC 9979 attribute. Memos, scheduled mail and snoozed mail remain accessible through their folders and ordinary message views.

| RFC 9979 metadata | Recognized | Preserved from server | Display | Edit |
| --- | --- | --- | --- | --- |
| `$MailFlagBit0`, `$MailFlagBit1`, `$MailFlagBit2` | Yes | Yes | Flag color label | Labels dialog and mail rules |
| `$hasattachment`, `$hasnoattachment` | Yes | Yes | Existing attachment detection | — |
| `$memo`, `$hasmemo` | Yes | Yes | Ordinary messages and folders | — |
| `$canunsubscribe`, `$unsubscribed` | Yes | Yes | — | — |
| `$autosent`, `$imported`, `$istrusted`, `$maskedemail` | Yes | Yes | — | — |
| `$followed`, `$muted`, `$new`, `$notify` | Yes | Yes | — | — |
| `Memos`, `Scheduled`, `Snoozed` | Yes | Yes | Ordinary folders | — |

## Flag colors

Starred IMAP and JMAP mail can have one flag color label: Orange, Yellow, Green, Blue, Purple or Gray. The ordinary star is also the display for the RFC's red flag, whose bit pattern is zero. Unstarred messages and the unassigned bit pattern show no color label.

The Labels dialog has a Flag color group. Setting a color stars the selected copies and replaces their previous colors. Removing the active color or turning off the star clears all three color keywords. An ordinary new star starts with clear color bits. On IMAP the color belongs to the selected folder copy. On JMAP the color belongs to the exact Email ID, so it may be shown in several folders for that Email ID. Searches and conversation lists show the color of the copy they represent.

The sidebar and Filters can find a flag color. Mail rules can test, set or remove colors. An ordinary label with the same name can still be used independently. The color controls are available for IMAP and JMAP mail. IMAP servers must support persistent keywords in a mailbox to set a color there.

## Existing installs

Database schema 154 moved previous provider status keyword labels to metadata. Schema 156 extends the existing message queue to carry pending color edits. A legacy keyword with uncertain copy provenance remains historical data. Gofer flags saved searches and rules that still refer to retired flag bit labels so their owners can choose a replacement. Each old keyword was one bit of a color, so Gofer leaves those references as written.

The next IMAP flag sync on a folder establishes a new metadata baseline. JMAP does one resumable import to retrieve metadata previously skipped by its cursors. IMAP represents a logical message once per folder, so duplicate UIDs with the same Message-ID in one folder share that representation. When an IMAP server resets a folder's UIDVALIDITY, a queued color edit for an obsolete UID expires. Gmail and Outlook API sync and local folders keep their existing behavior. IMAP accounts use the IMAP behavior above regardless of server vendor.

## Follow-up work

A later memo feature would need to pair notes with their annotated messages and present them in context. Attachment indicators still use the existing message attachment data. Attachment keyword handling, subscription state, advisories and thread actions each need their own provider behavior and UI. The mailbox attributes identify storage locations. Snoozing and scheduled sending need provider-specific mechanisms for timing and cancellation.

[RFC 9979](https://www.rfc-editor.org/rfc/rfc9979.html) defines the registrations and behavior. Work is tracked in [issue #159](https://github.com/cristianadrielbraun/gofer/issues/159).
